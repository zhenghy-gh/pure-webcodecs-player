## 一、核心事实：浏览器的网络沙箱限制（不是协议解析能力的限制）

| 目标库 | 直连可行性 | 结论 | 落地形态 |
|--------|-----------|------|----------|
| `mov.js` | ✅ | 完全可纯前端 | 本地 File / HTTP Range → ISO-BMFF 解析 → WebCodecs → Canvas |
| `mp4.js` | ✅ | 完全可纯前端 | 同上，输出 MSE 或 WebCodecs |
| `hls.js` | ✅ | 可纯前端 | m3u8 解析 + TS/fMP4 分片 → MSE |
| `flv.js` | ✅ | 可纯前端（HTTP-FLV 输入） | FLV Tag 解析 → MSE |
| `mkv.js` | ✅ | 可纯前端（难度高） | EBML 解析 → Demux → WebCodecs → Canvas |
| `ts.js` | ✅ | 可纯前端 | PAT/PMT/PES → H264/AAC → WebCodecs |
| `cmaf.js` | ✅ | 可纯前端 | CMAF Chunk → ISO-BMFF → WebCodecs（LL 流媒体方向） |
| `wav.js` | ✅ | 可纯前端 | RIFF 解析 → AudioWorklet/WebAudio |
| `flac.js` | ✅ | 可纯前端 | FLAC 解码 → AudioWorklet |
| `ape.js` | ✅ | 可纯前端（解码器复杂） | APE 头解析 + 解码 → WebAudio |
| `subtitle.js` | ✅ | 可纯前端（难度低） | ASS/SSA/SRT 解析渲染（libass-wasm 或 JS 实现）→ Canvas |
| `webtorrent.js` | ✅ | 可纯前端 | torrent → piece → mp4 → WebCodecs，P2P 边下边播 |
| `webrtc.js` | ✅ | 可纯前端 | webrtc:// 信令 → RTCPeerConnection，延迟 200ms~1s |
| `rtmp.js` | ❌ 直连 / ⚠️ 桥接 | 浏览器无 TCP API | **WebSocket 网关桥接**：本质是 “WebSocket-FLV 播放器” |
| `rtsp.js` | ❌ 直连 / ⚠️ 桥接 | 浏览器无 UDP API（RTP over UDP 不可达） | **WebSocket 中继**（RTSP interleaved / RTP over TCP）或 WebRTC 网关 |

## 二、HTML 给出的推荐总架构（“下一代 ffplay.js”）

```
                 Player Core（统一播放内核）
                        |
      ----------------------------------------
      |         |         |         |        |
   MP4.js    MKV.js    TS.js    FLV.js    HLS.js ...
                        |
                    WebCodecs（解码）
                        |
              Canvas/WebGPU + AudioWorklet（渲染）
```

- 统一管线：`Container → Demuxer → Codec → WebCodecs → Renderer`
- 服务端只负责“协议入口”（RTMP/RTSP/SRT/GB28181 → WebSocket/WebRTC 网关），前端做媒体管线。
- RTMP 最佳实践：`RTMP → HTTP-FLV → flv.js` 或 `RTMP → WebRTC`；
  RTSP 摄像头最佳实践：`RTSP → WebRTC` 或 `RTSP → HLS`；追求极低延迟/免转码时用 `RTSP → WebSocket → WebCodecs`。

## 三、延迟量级参考（选型依据）

| 方案 | 典型延迟 |
|------|---------|
| 普通 HLS | 5～30 秒 |
| LL-HLS | 1～5 秒 |
| HTTP-FLV | 1～3 秒 |
| WebRTC | 200ms～1 秒 |
| WebSocket 自定义流 | 几百毫秒级 |
| WebSocket 桥接价值场景 | 监控云台控制、实时机器视觉、工业控制、远程操作、免转码直推裸流 |

## 四、HTML 的分阶段路线建议

1. 第一阶段：`mov.js` / `mp4.js` / `flv.js` —— 输入 File / ArrayBuffer / Fetch，输出 MSE / WebCodecs
2. 第二阶段：`ws-player.js` —— 自定义低延迟流（header/timestamp/codec/frame data）
3. 第三阶段：`rtsp.js` / `rtmp.js` —— 桥接形态（Gateway → ws:// → js 客户端）
